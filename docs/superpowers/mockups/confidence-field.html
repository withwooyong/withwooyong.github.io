② 노드 상세 패널 — 배지 한 개 추가

서브에이전트는 컨텍스트 방화벽이다

CLAIM내 생각working

탐색 과정이 컨트롤러 컨텍스트에 들어오지 않는다. 돌아오는 것은 최종 보고서뿐이다.

연결

contradicts  컨텍스트는 크면 좋다 (2024, settled→폐기)

↑ 배지 하나가 붙는 게 전부입니다. 위 contradicts 줄과 만나면 "생각이 바뀐 경로"가 읽힙니다.

"아직 가설인 것만 보기"가 가능해집니다. 방문자에게는 지금 고민 중인 지점이 그대로 보입니다.

④ 그래프 — 노드 형태로 구분
settled — 꽉 찬 원
working — 반투명

렌더러가 값 하나로 스타일만 분기합니다. 렌더러 교체 구조라 여기가 싸게 끝납니다.

넣었을 때 / 안 넣었을 때

항목넣는다안 넣는다
구현 비용 프론트매터 1줄 + 배지 1개 + 렌더러 분기 1개 + 렌즈 1개. 반나절 수준 0
운영 부담 진짜 비용은 여기입니다. 노드마다 값을 성실히 유지해야 합니다. 방치하면 전부 working으로 남아 렌즈가 무의미해집니다 없음
나중에 추가하면 — 노드 수천 개를 소급해서 채워야 합니다. 필드 추가는 싸지만 소급 입력은 비쌉니다
독자에게 주는 것 "이 사람은 자기가 모르는 걸 안다" — 20년차 리더에게 가장 강한 신호. 참고 사이트에 없는 차별점 —
A

넣는다 — 렌즈까지 전부

필드 · 배지 · 렌즈 · 노드 스타일 4곳 모두. 값 유지는 2단계 LLM 추출 때 제안받고 사람이 교정합니다.

B

필드만 넣고 UI는 나중에

스키마에는 지금 넣어 소급 입력을 피하되, 배지·렌즈는 값이 실제로 다양해진 뒤에 켭니다. 소급 비용만 회피하는 안전한 선택.

C

넣지 않는다

origin(외부 vs 내 생각)만으로 충분하다고 보고 스키마를 단순하게 유지합니다.

## 3. ⚠️ 초과분 22.4KB의 분해 — 뒤 배치 결정 사항

편2~5만 보면 설계 63.4KB → 실측 85.8KB, **+22.4KB**다. 인상이 아니라 바이트로 나눴다.

| # | 항목 | 바이트 | 성격 |
| ---: | --- | ---: | --- |
| 1 | frontmatter 4편분 (677·705·626·701) | **2,709** | 원본 「머리말」이 §1 사슬에서 빠져 **원본 B 열에 계상되지 않음** |
| 2 | 축약 용어표 3편분 (편3 1,474 · 편4 1,292 · 편5 1,107) | **3,873** | §4-4가 승인했으나 **원본 B는 편2에만 계상** |
| 3 | 표 요약문 · 도입/마무리 · 편간 링크 문단 · 인용 조건 각주 | **~15,800** | **변환자 판단분** |
| | **계** | **~22,400** | |

**1·2번(6.6KB)은 설계서의 계상 방식에서 나온 구조적 차이지 변환자의 재량이 아니다.** §4-1 「원본 B」 열이 머리말과 축약표를 포함하지 않으므로, 배율 1.2를 곱해도 이 6.6KB는 나올 수 없다.

**3번이 변환자 판단분이며 실질 초과다.** 근거는 둘이다.

| 근거 | 실측 |
| --- | --- |
| 문서 작성 규칙이 **표마다 한 줄 요약**을 요구한다 | 편2~5에 표 **52개**. 요약 1줄당 150~250B면 **~9.4KB**가 규칙만으로 발생한다 |
| 발행본 표본(`harness-five-primitives`)의 문체가 **표 뒤 인용블록 해설**이다 | 표본 실측 20.3KB 중 인용블록 9개 |

> **`02`는 표 밀도가 비정상적으로 높다.** 설계 §10-1 실측으로 `02`는 59,773B에 표 52개 —
> 1,150B당 표 1개다. 팽창률 1.2는 `ai-agent`(1.33)·`rag`(1.11) **전체 평균**에서 뽑은 값이라
> 표 밀도를 반영하지 않는다. 표가 많은 파일일수록 「표마다 한 줄 요약」 규칙의 비용이 커진다.

### 3-1. 컨트롤러 결정 요청

**나는 초과분을 줄이지 않았다.** 이유와 선택지를 함께 적는다.

| 선택지 | 내용 | 결과 |
| --- | --- | --- |
| **A (현 상태)** | 1.7× 를 이 원본의 실제 배율로 인정 | 26편 총량이 468.2KB → **~660KB** 로 재추정됨 |
| B | 표 요약을 「3개 이상 항목 표」로만 한정 | 편당 ~2KB 감소. 문서 작성 규칙과 충돌 |
| C | 편간 링크 문단·인용 조건 각주 축약 | 편당 ~1KB. **§6-5 조건 이관이 얇아져 권장하지 않음** |

**A를 권고한다.** 하한(13.3) 위반이 없고 상한 분포(29.4) 안이며, 줄이는 대상이 전부 **설계서가 명시로 요구한 항목**(표 요약·조건 이관·편간 링크)이기 때문이다. 다만 **§10 검산 기준값의 「본문 26편 468.2KB」는 재추정이 필요**하다 — 설계서 수정 권한이 없어 보고만 한다.

## 4. `강의` 처리 내역 — 전수 실측

### 4-1. 모집단 — 설계서 진단의 정정

> **정정 (2026-08-08, 독립 검증 3기 반영)** — 초판은 `01`을 **17행**으로 적었다. 실측은 **18행**이다.
> 아래 표와 §4-2 갈래표를 정정했다. 발행물에는 영향이 없다(범위 내 6건은 초판에서도 전건 정확).

| 대상 | 설계서 §6-1 | **B1 실측** |
| --- | ---: | ---: |
| `강의` 행 수 | 160 (전 파일) | `02` **19행** · `01` **18행** |
| `강의가 ~한다` 형태 | 130여 (전 파일) | `02`에서 **0건** |
| (검증 3기 실측) `강의가`+`강의는` 전 파일 | — | **32건** — 설계서 「130여 개」는 **약 4배 과대** |

> **설계서의 160행은 전 파일 합계로 맞으나 「130여 개」는 실측 32건이다.** 초판은 「12편 전체
> 모집단」이라는 틀만 정정하고 **130이라는 값 자체는 검증 없이 승계했다.** 독립 검증이 전 파일
> `grep -oh "강의가\|강의는"`로 32를 실측했고, 잔여 9편의 주어 교체 대상은 **26~47건**이다.
> 뒤 배치의 작업량 추정을 이 값으로 잡아야 한다.
>
> **부수**: 원본은 `00`~`10` **11개 파일**이다. 설계서·커밋 메시지의 「12편」과 어긋난다.
> 브리프가 「최대 작업량 — `강의` 160행 처리」로 제시한 것은 카테고리 전체 예고치이며,
> `02`에서 `강의가 ~한다`(주어 형태)는 **한 건도 없었다.** 전부 관형어(`강의 자료`·`강의 기준`·
> `강의 인용값`)이거나 귀속 서술이다. **주어를 갈아 끼우는 작업은 B1에서 발생하지 않았다.**
> 뒤 배치는 이 결과를 액면가로 받지 말고 담당 파일에서 다시 세야 한다 — `01`은 L77·L109·L123
> 등에서 실제로 `강의가/강의는 ~한다` 형태를 쓴다(단 그 절들은 전부 드롭 대상이다).

| | 문장 |

| 7 | **frontmatter(~680B)와 축약 용어표(~1,300B)는 「원본 B」 열에 없다.** 편당 ~2KB가 배율 계산 밖에서 발생한다 | §3 표 1·2행 |

### 10-1. 작업트리 상태 (변환 완료 시점)

```
 M content/blog/tags.ts                                        ← 컨트롤러 (설계 §8-1)
 M docs/superpowers/specs/2026-08-07-tech-blog-requirements.md ← 컨트롤러 (설계 §2-1)
?? content/blog/agentic-coding/                                ← 본 배치 산출 5편
?? docs/superpowers/reports/                                   ← 본 보고서
```

**변환자가 만든 것은 `??` 두 항목뿐이다.** `M` 두 건은 변환자가 손대지 않았으며,
`tags.ts`는 **주석 1줄만** 바뀌고 어휘 배열은 그대로라 §8의 태그 검증 결과에 영향이 없다.

**원본 디렉터리(`yanadoo-exit`)는 읽기만 했다** — `git status --porcelain` 출력이 비어 있음을 확인했다.

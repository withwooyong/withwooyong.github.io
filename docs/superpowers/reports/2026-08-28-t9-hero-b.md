### Ruling R35 — 「대조군이 있다」와 「대조군이 유효하다」는 다르다

F2 가 이것이다. `accent-area.test.ts` 에는 처음부터 대조군이 있었다 —
「노드 24개를 전부 액센트로 칠하면 5%를 넘는다」. 그런데 그 대조군은 **표본 64개에서도 3.1%p 를 넘겨
통과한다.** 측정 대상보다 5~50배 큰 케이스로 보정돼 있어 격자 해상도가 무너져도 살아남는다.

대조군의 목적은 「계수기가 살아 있다」를 증명하는 것인데, **너무 쉬운 대조군은 계수기가 반쯤 죽어도
살아 있다고 말한다.** 처방은 「측정 대상과 같은 크기의 원 1개를 해석해 `π·r²/면적` 와 대조」다.

여기서 나온 부수 발견이 더 중요하다.

> **표본 해상도의 오차는 단조가 아니라 격자와 원의 정렬 운에 좌우된다.**
> 표본 128 에서 desktop 은 오차 1.65% 로 통과하고 mobile 은 10.3% 로 걸린다.
> **desktop·mobile 두 뷰포트를 도는 루프가 중복이 아니라 이 검사의 유일한 방어선이다.**

이 문장은 테스트 파일 주석에 박아 뒀다. 「둘 다 볼 필요 있나」 하고 하나를 지우면 검사가 조용히 헐거워진다.

**한계도 함께 기록한다** — 표본 256 은 두 뷰포트 모두 통과한다. 그 해상도의 실측 오차는 상대 ~1% 라
5% 예산에 무해하므로 위험이 아니라 한계다. **모든 뮤턴트를 죽이는 테스트는 없고, 어디까지 잡는지를
아는 것이 잡는 것만큼 중요하다.**

### Ruling R36 — 주석이 틀린 것은 코드가 틀린 것보다 비싸다

F1 의 주석은 이렇게 적혀 있었다.

> *「Nanum(구글폰트)는 건드리지 않았다. 이미 차단 요청이 아니기 때문이다 —
> Next 가 `post-process.js` 에서 빌드 시점에 CSS 를 받아 head 에 인라인한다.」*

**Next 문서상 맞는 문장이다.** 그런데 이 빌드에서는 거짓이었다. 인라인에 실패하면
`post-process.js` 가 **head 맨 끝에 원본 링크를 그대로 복원**한다. 산출물에는
href 없는 죽은 링크 하나와 살아 있는 차단 링크 하나가 함께 남아 있었다.

**코드 결함은 다음 사람이 실측하면 발견하지만, 그럴듯한 주석은 실측을 하지 않게 만든다.**
정정하면서 주석에 확인 명령을 함께 넣었다 — 「이 주석을 믿지 말고 `npm run build` 후 head 에서
`media` 도 `data-href` 도 없는 서드파티 스타일시트를 세라. 0 이어야 한다.」

처방의 기전도 기록해 둔다. **URL 을 React 트리에서 빼는 것이 유일하게 확정적인 회피다.**
최적화기는 `<Head>` 의 엘리먼트만 훑으므로 스크립트 문자열 안의 URL 에는 손대지 못한다.
`media=print` 가 최적화기를 이기는 것이 아니다 — jsdelivr 가 무사했던 것은 그 목록에 없어서다.

### Ruling R37 — reduced-motion 의 최종 상태는 JS 가 아니라 CSS 로 만든다

F6 이 이것이다. 정적 export 라 서버 HTML 은 `useState(0)` 으로 직렬화되고,
`useEffect` 는 **페인트 뒤에** 돌아 `setProgress(1)` 을 한다. 그래서 모션을 끈 사용자가
정확히 「첫 문장이 보였다가 최종 상태로 튀는」 한 번의 큰 변화를 본다 — 줄이려던 바로 그것이다.

**SSR 은 `prefers-reduced-motion` 값을 모르므로 페인트 뒤 `setState` 로는 원리상 없앨 수 없다.**
Tailwind 의 `motion-reduce:` 변종으로 옮기면 첫 페인트부터 CSS 가 최종 상태를 그린다.
껍데기 높이까지 `motion-reduce:h-screen` 으로 옮겨 200vh 죽은 스크롤도 함께 사라졌다.

`setProgress(1)` 경로는 지우지 않고 폴백으로 남겼다. **`MediaQueryList.addEventListener` 로
설정 변경을 구독하지 않은 것도 의도다** — 그 API 가 구형 사파리에서 TypeError 를 던져
React 루트를 언마운트시키고 전 페이지를 백지로 만든 전력이 있고(R34), 에러 바운더리는 0건이다.
로드 후 OS 설정을 바꾸면 죽은 스크롤이 되돌아오지만 새로고침하면 정상이다 —
**설정을 바꾸고 새로고침을 안 하는 경우보다 백지가 훨씬 비싸다.** 코드가 아니라 주석에 남겼다.

### ⑦ 편1 — 신규 도식이 원본에 없는 되먹임 고리를 닫음

**전**

```
R["복구 지점 밀도"] --> C["복구 비용"]
C --> P["부여 가능한 권한 폭"]
P --> A["자동화 효용"]
C -->|"높으면"| N["권한 축소 → 효용 하락"]
A --> R                        ← 원본에 없는 역방향
```

**후**

```
R["복구 지점 있음"]   -->|"되돌릴 수 있으면"| P["넓은 권한 부여 가능"]
P -->|"권한이 넓으면"| A["자동화 효용 확보"]
R2["복구 지점 없음"]  -->|"되돌릴 수 없으면"| P2["넓은 권한 불가"]
P2 -->|"권한이 좁으면"| A2["자동화 효용 하락"]
```

- **역방향 화살표 `A --> R` 삭제.** 원본 `01` L314는 단방향 사슬이다.
- **라벨 불일치 해소**: 전 도식은 무라벨 화살표와 조건 라벨 화살표가 섞여 있었다. 후 도식은 **네 화살표 전부에 조건 라벨**을 달았다.
- 원본이 실제로 쓴 것은 **부정 방향**(되돌릴 수 없으면 → 권한 불가 → 효용 하락)이라 아랫줄로 그대로 옮기고, 윗줄을 그 대우로 뒀다.

해설도 「이 순환에서」 → **「두 줄은 같은 사슬을 양방향으로 읽은 것이고, 원 자료가 명시한 것은 아랫줄이다」** 로 교체했다. **도식 수는 2 그대로다.**

| L647 → `settings-permissions-deny.md:123` 「모드 (원 자료 표기)」 | ✅ 존재 |

**장부만 틀렸고 산출물은 옳았다.** 다만 상쇄 오차는 합계 검산을 통과하므로 스스로 드러나지 않는다 — 뒤 배치가 이 표를 템플릿으로 쓸 때 같은 실수가 나면 상쇄되지 않아 실제 누락이 된다.

## 7. 작업트리 상태

```
 M content/blog/tags.ts                                        ← 컨트롤러 (설계 §8-1)
 M docs/superpowers/specs/2026-08-07-tech-blog-requirements.md ← 컨트롤러 (설계 §2-1)
?? content/blog/agentic-coding/
?? docs/superpowers/reports/
```

두 디렉터리가 아직 **미추적**이라 개별 파일이 `M`으로 뜨지 않는다. 이번 라운드에서 내가 손댄 파일은 아래 여섯이다.

| 파일 | 변경 |
| --- | --- |
| `content/blog/agentic-coding/reversibility-before-permission.md` | ① ⑥ ⑦ ⑧ ⑫ ⑭ B-1 + 선택 §8 |
| `content/blog/agentic-coding/claude-code-autonomy-tiers.md` | ② ④ ⑩ B-3(b) |
| `content/blog/agentic-coding/builtin-tools-attack-surface.md` | ③ ⑨ ⑬ ⑮ B-2 |
| `content/blog/agentic-coding/claude-md-enforcement.md` | ⑤ ⑪ B-3(a) |
| `content/blog/agentic-coding/settings-permissions-deny.md` | **무변경** (20,434 B 동일) |
| `docs/superpowers/reports/2026-08-08-B1-conversion-report.md` | §1 주 · §4-1 · §4-2 정정 |

`M` 두 건은 **컨트롤러가 병행한 작업**이며 내가 손대지 않았다.

| 금지 사항 | 준수 |
| --- | :---: |
| `git commit`·`git push` | 미실행 ✅ |
| 원본(`yanadoo-exit`) 수정 | 읽기만 — `git status --porcelain` 빈 출력 ✅ |
| 설계서·요구사항·`tags.ts` 수정 | 미수정 ✅ |

**설계서 정정 1건이 남아 있다** — §6-1 L519의 「130여 개」는 실측 32다. 뒤 8개 배치 계획에 직접 물려 있어 파급이 가장 크나 **수정 권한이 없어 보고만 한다.**

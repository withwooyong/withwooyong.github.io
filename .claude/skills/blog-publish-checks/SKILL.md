# 발행 전 검사와 뮤테이션

루트 `CLAUDE.md` 의 「증명하기 전에는 0을 믿지 마라」와 검사기 수 규칙을 전제로 한다.

## 발행 전 검사 — `content/blog/` 를 건드릴 때마다

| 명령 | 무엇을 검사하나 |
| --- | --- |
| `npm run check-forbidden:verify` | **가장 먼저.** 금칙어 스캐너가 실제로 잡는지 증명한다 |
| `npm run check-forbidden` | `content/blog` 스캔. 발행 전 **HARD 0** 이어야 한다 |
| `npm run check-forbidden:built` | **빌드 산출물**(`out/blog` + `_next/data`) 스캔. 빌드 뒤에 돌린다. 템플릿이 `og:image` 와 제목을 주입하므로 **소스가 깨끗해도 페이지는 오염될 수 있다.** 산출물이 없으면 거짓 0 대신 종료 코드 2 |
| `npm run check-markup:verify` → `npm run check-markup` | 🔴 **렌더되지 않는 강조.** 기존 검사 다섯은 낱말과 바이트만 보고 **마크업 문법을 보지 않아** 별표가 화면에 찍힌 편이 75개·306회 쌓였다. 판정은 정규식이 아니라 **페이지를 그리는 파서**가 한다 — 코드 블록 안의 정당한 예시 109회가 저절로 빠진다. 기전이 둘이라 정규식으로는 반쪽만 잡힌다 |
| `npm run check-markup:docs` | 🔴 **발행본 밖의 리포 문서.** 위 명령은 `content/blog/` 만 보므로 설계서·인수인계·`CLAUDE.md` 는 아무도 보지 않았고, 그 사이 **250회**가 쌓였다. 대상 수집은 검사기가 직접 한다 — 호출부에서 `git ls-files` 로 뽑아 넘기지 마라. `core.quotePath` 기본값이 한글 경로를 따옴표로 감싸는 바람에 54개 중 **4개가 조용히 빠진** 적이 있다 |
| `npm run check-links:verify` → `npm run check-links` · `npm run check-links:docs` | 🔴 **깨진 링크.** 발행본은 `/blog/<카테고리>/<슬러그>/` 만 유효하고 상대 `.md` 는 정적 export 에서 **반드시 404** 다. 문서는 그 파일이 실제로 있어야 하며 **기준은 리포 루트가 아니라 그 문서의 디렉터리**다 — 실측 22곳이 루트 기준으로 적혀 있었다. 판정은 파서가 한다: 정규식으로 세면 코드 블록 안의 예시가 위반이 되고 앵커를 벗기지 않으면 멀쩡한 편이 위반이 된다 (실제로 둘 다 겪었다) |
| `npm run check-mermaid:verify` → `npm run check-mermaid` · `npm run check-mermaid:docs` | 🔴 **그려지지 않는 도식.** 리포에 Mermaid 블록이 🆕 **696개**(발행본 558 · 문서 138 — 2026-09-16 에 상태 다이어그램, 2026-09-17 에 시퀀스 다이어그램을 하나씩, 같은 날 플로우차트 여섯(두 편)을 SVG 로 옮겼다) 있는데 문법이 어긋나면 화면에는 흐름도 대신 빨간 오류 상자가 뜬다. 판정은 정규식이 아니라 **화면을 그리는 mermaid 파서**가 한다. 🔴 위험은 위반을 놓치는 것이 아니라 **거짓 0** 이다 — Node 에는 DOM 이 없어 파싱에 닿기도 전에 죽는데 그것을 「위반 없음」으로 세면 초록이 나온다. **실측 649개 중 621개가 그렇게 빠졌다.** 그래서 검사기는 판정에 **도달한** 수를 함께 세고, 카나리 도식 하나를 먼저 파싱해 파서가 살아 있는지 본다. 못 미치면 종료 코드 2. 🔴 **이 검사기는 파싱만 보고 배치는 보지 않는다** — 뜻이 위아래로 뒤집힌 도식도 문법은 정상이라 영원히 위반 0 이다(함정 54) |
| `npm run check-table:verify` → `npm run check-table` · `npm run check-table:docs` | 🔴 **셀 수가 머리 행과 어긋난 표 행.** 위 검사 넷은 낱말 · 강조 · 링크 · mermaid 문법을 볼 뿐 **표의 구조를 보지 않아** 어긋난 행 4곳(발행본 2 · 문서 2)이 셋을 전부 통과했다. GFM 은 이것을 오류로 만들지 않는다 — 초과분을 **버리고** 모자란 칸을 빈 칸으로 채우므로 **깨지는 대신 조용히 다른 것이 그려진다.** 기전 넷 중 셋이 **코드 스팬 안의 세로줄**이다. 판정은 정규식이 아니라 파서가 한다 — 코드 블록 안의 표 예시가 저절로 빠진다 |
| `npm run fix-markup:verify` → `npm run fix-markup -- --category <slug>` | 위 위반의 교정. 조사를 강조 **안으로** 옮긴다. **알려진 조사일 때만** 자동이고 아니면 손볼 자리로 남긴다 — 기계가 조사의 경계를 안다는 전제를 두지 않는다. `--dry` 로 먼저 본다. 바이트가 보존되므로 **분량 예산과 역산 배율이 흔들리지 않는다** |
| `npm run dup-scan:verify` → `npm run dup-scan -- --category <slug>` | 축자 복제 스캔. 순서는 같다 — 증명한 뒤 스캔. 대상이 없으면 종료 코드 1. 배치를 통째로 넘겨도 안전하다 |
| `npm run source-overlap:verify` → `npm run source-overlap -- <발행본> <원본>` | **원본** 대조. `dup-scan` 은 발행본끼리만 보므로 리포 밖 원본과의 겹침은 여기서만 잡힌다. 공백 보존·공백 제거 두 정규화를 모두 돌리고, 도식 라벨은 임계값이 아니라 **통째 일치**로 판정한다 |
| `npm run check-counts:verify` → `npm run check-counts` | 🔴 **README 의 발행본 수**가 실제와 맞는지. 이 표에서 빠져 있던 탓에 **편2~7 동안 Pages 배포가 계속 실패했다** — 로컬 빌드도 pre-commit 훅도 이것을 보지 않고 CI 의 `Check documented counts` 에서만 죽는다. 편을 발행했으면 **네 자리**를 같은 커밋에 넣는다 — README 셋(요약표 · 디렉터리 트리 · 카테고리 내역)과 **CHANGELOG 의 「총 N편」** 이다. 🔴 이 항목이 오래 「세 자리」로 적혀 있었고 실제로 그 넷째에서 걸렸다. 자리 수를 문서에서 읽지 말고 **검사기의 출력 끝줄(「검사한 자리 N곳」)에서 읽어라** |
| `npm run search-index:verify` → `npm run search-index` | 🔴 **검색 인덱스.** `out/_next/data` 의 `post.toc` 를 재사용해 `out/blog/search-index.json` 을 만든다 — 소스를 다시 파싱하지 않으므로 헤딩 텍스트와 앵커 id 의 진실원이 하나다. `npm run build` 안에서 sitemap 다음에 돈다. 가드 다섯이 **대상 없음 · buildId 모호(디렉터리가 둘 이상이면 사전순 첫 항목을 고르지 않고 종료 2) · 수 대조(184 = 184) · 카나리 · `decideExit` 순수 함수**를 본다. 루트가 아니라 `out/blog/` 아래에 두는 이유는 `check-forbidden --built` 의 스캔 범위이기 때문이다 — 루트에 두면 제목·설명·헤딩 2,671개가 금칙어 검사를 우회한다 |
| `npm run compose -- <발행본>` | **복제를 지운 뒤 다시 돌린다.** 겹침을 피해 고쳐 쓴 문장은 원래보다 길어져 분량이 는다 — 실측 **+232 B** 로 밴드 상단 여유가 296 에서 **65** 로 줄었다. 밴드를 판정한 값과 실제 발행되는 값이 **다른 파일**이 되는데, 검사도 빌드도 통과하므로 다음 편에서 배율을 역산할 때에야 드러난다 |
| `npm run check-handoff:verify` → `npm run check-handoff` | 🔴 **HANDOFF 가 다시 쌓였는지.** 네 절(지금 상태 · 남은 작업 · 다시 읽을 것 · 도구 함정) · 150줄 상한 · 「세션이 한 일」 제목 금지. 문서 커밋의 훅과 CI 에서 돈다. 걸리면 줄이지 말고 **덮어써라** |
| `npm run check-engines:verify` → `npm run check-engines` | 🔴 **CI 의 Node 에서 돌지 않는 의존성.** `npm install` 은 `engines` 를 강제하지 않으므로 로컬 Node 에서만 만족되는 판이 **경고 없이** 설치되고 CI 에서만 죽는다. 실측으로 두 번 겪었다 — jsdom 30, 그리고 발표본 의존성 넷. 🔴 **둘째는 직접 의존성이 아니라 transitive 였다.** 그래서 직접 의존성만 보면 잡히지 않아 **설치된 트리 전량**(실측 **372개**)을 본다. 🆕 발표본 갈래를 걷어낸 뒤 대상 트리는 리포 루트 하나이고, 대조군을 Node 20 에서 **16** 으로 낮췄다 — 종전 대조군의 위반이 전부 발표본 트리에서 나왔으므로 그대로 두면 헛돈다. 정본은 워크플로의 `node-version` 이고, `node_modules` 가 없으면 거짓 0 대신 종료 코드 2 다 |

## 되돌려 보는 일은 손으로 하지 않는다 — `npm run mutate`

| 명령 | 무엇을 하나 |
| --- | --- |
| `npm run mutate:verify` | **먼저.** 러너 자신이 작동하는지 — 뮤턴트가 실제로 적용되고, 검사 뒤 파일이 **바이트까지** 복구되는지 |
| `npm run mutate` | 알려진 결함 **132개**를 하나씩 되살려 검사 **열네 개**(스크립트 검사기 열네 종 중 `check-counts` 를 제외한 열셋 + `blog-unit` Vitest)의 자기 검사가 잡는지 본다. **생존이 하나라도 있으면 종료 코드 1**. 🔴 **소요는 121개 기준 29분 40초다**(2026-09-12 실측) — 「3~5분」으로 적혀 있던 값이 뮤턴트와 검사가 함께 늘어 곱으로 커졌다. **세션 끝이 아니라 시작에 백그라운드로 걸어라** |

**검사기를 고쳤으면 이것을 돌려라.** 자기 검사의 통과는 「케이스가 있다」만 말할 뿐
「그 케이스가 무언가를 지킨다」는 말하지 않는다. 실측으로 `source-overlap` 은
임계값을 20 → 200 으로 바꿔 실제 스캔이 52자 축자 복사를 0건으로 보고하는 동안에도
**28/28 을 그대로 냈고**, `dup-scan` 은 공용 정규화를 통째로 무력화해도 **7/7 을 냈다.**

⚠️ **「치환 실패」는 러너의 고장이 아니라 신호다.** 뮤턴트의 대상 문자열은 실제 코드 조각이라,
코드를 고치면 못 찾는다. 그때는 **그 자리를 다시 볼 때가 된 것이므로** 종료 코드 1 로 다룬다.

⚠️ **없는 것을 소스에 리터럴로 적으면 그 순간 존재하게 된다.** 러너의 자기 검사가 「없는
문자열」을 코드에 적었다가 자기 자신에 매칭돼 헛돌았고, 같은 실수를 `source-overlap` 의 ⑰-b
(케이스 **이름**에 상수 이름을 적어 자기 자신을 매칭)에서도 했다. 이름의 등장이 아니라
**호출의 인자**를, 리터럴이 아니라 **런타임 조합**을 보라.

⚠️ **필터를 통과한 집합으로 그 필터를 검사할 수 없다.** 「수집한 경로가 전부 `.md` 로
끝난다」는 케이스가 자기 검사 21/21 안에서 계속 PASS 였는데, `core.quotePath` 를 켜면
한글 경로는 **있지도 않은 이름**이 되어 `existsSync` 에서 걸러지고 남은 것은 정의상
조건을 만족한다 (실측 54개 대 50개). ⇒ **대조할 것이 실제로 있는지를 먼저 세라.**
그리고 **가드는 `main` 이 아니라 순수 함수로 뽑아라** — 흩어져 있으면 통째로 지워도
케이스가 전부 통과한다.
